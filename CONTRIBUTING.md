# Как править as-skill

Это личная коллекция, но устроена так, чтобы её можно было форкнуть и вести дальше. Ниже — правила, которые держат репозиторий в порядке.

## Один источник правды

Редактируется **только `domains/`**. Никакого сгенерированного зеркала в корне репозитория нет: `.claude/` — гитигнорится и представляет собой не копию, а **symlink-установку** `domains/` через инсталлятор `as-skill` — правки под `domains/` видны в ней сразу, без пересборки и без отдельного шага синхронизации. Пересоздать её с нуля, если разъехалась или удалилась:

```bash
rm -rf .claude
./as-skill install domains code git core --project .
```

`as-skill install ... --copy` вместо symlink делает независимый снэпшот — этим режимом ставят, например, домен `code` в чужой проект (`as-skill install domains code core --project <path> --copy`). Подробности обоих режимов — в `CLAUDE.md` и `tools/README.md`.

## SKILL.md и README.md — разные документы

`SKILL.md` — промпт для модели. Пишется в императиве, содержит алгоритм, границы применимости и раздел «чего не делать». Модель читает его целиком при срабатывании, поэтому лишний текст стоит денег в каждом вызове.

`README.md` рядом — объяснение для человека, который листает GitHub и решает, нужно ему это или нет. Что делает, когда срабатывает, пример до/после.

Не сливай их в один файл и не копируй один в другой.

## Добавление скилла

1. `domains/<домен>/skills/<имя>/SKILL.md` с фронтматтером `name` и `description`.
2. Имя каталога и `name` во фронтматтере должны совпадать — это проверяет `as-skill check`. Префикс домена (`git-`, `obsidian-`, …) в имени — конвенция из `CLAUDE.md`, автоматически пока не проверяется, но её всё равно держим.
3. `README.md` рядом.
4. Если скиллу нужен исполняемый помощник или справочный материал — `scripts/` и `references/` рядом с `SKILL.md` (так устроены `git-conventional-commits`, `git-release-tag`, `content-humanizer`). `SKILL.md` ссылается на них относительным путём и не дублирует их содержимое.
5. Обнови счётчик скиллов/агентов/правил/хуков домена в таблице «Домены» корневого `README.md`.
6. `go build -o as-skill ./tools && ./as-skill check && go test ./...` — собрать, прогнать self-check манифестов и `SKILL.md`, прогнать тесты `tools/`. Если правишь домен, установленный в корневой `.claude/` (сейчас это `code`, `git` и `core`), и хочешь увидеть новый скилл там же — `as-skill install` симлинкует записи поштучно, так что новый файл подхватится только после повторного `./as-skill install domains code git core --project .`.

`description` — единственное, по чему модель решает, звать скилл или нет. Пиши туда триггерные формулировки живым языком («написать постмортем», «разобрать инцидент»), а не абстрактное описание возможностей. Если два скилла могут сработать на одну фразу — разведи их описания явно, взаимными отсылками.

## Добавление хука

1. `domains/<домен>/hooks/<имя>.sh`, исполняемый (`chmod +x`). Хуки сейчас есть только у `code` и `core`.
2. В шапке — строка `# register: <Event> [<matcher>]` (например `# register: PostToolUse Edit|Write|MultiEdit|Bash`). По ней `/code-init` через `code-init/scripts/register-hooks.sh` прописывает хук в `.claude/settings.json` проекта — сам скрипт для нового хука не правится.
3. Fail-open: `set -Eeuo pipefail` + `trap 'exit 0' ERR`, нет нужного бинаря (`jq`, `claude`, …) или входных данных — `exit 0`.
4. Общая для нескольких хуков логика — в отдельный `*-lib.sh`, который хуки `source`-ят (пример — `test-gate-lib.sh`); у библиотеки нет строки `# register:`.
5. Опиши хук в `domains/<домен>/hooks/README.md` и добавь строку в таблицу «Хуки» корневого `README.md`. Если хук ходит в сеть или запускает что-то в фоне — раздел в `SECURITY.md`.

## Добавление домена

1. `domains/<имя>/{manifest.yaml, rules/, skills/, agents/, hooks/}` — всё, кроме манифеста, не обязательно (пример — `devops`, пока только `agents/`).
2. В манифесте — `name`, `description`, `requires_env`, `targets`; внешний CLI объявляется через `requires_bin`.
3. Все компоненты домена получают префикс `<имя>-`.
4. Строка в таблице «Домены» корневого `README.md`.

## Требования домена

`requires_env` — переменная окружения. Не задана — `as-skill install all` пропускает домен целиком, с предупреждением; явный `as-skill install domain|domains|skill` по этому домену вместо этого падает с ошибкой.

`requires_bin` — та же логика поверх `exec.LookPath`, для внешнего CLI. Нужна, когда часть домена работает поверх внешнего инструмента, а часть — нет: без неё отсутствие одного бинаря уносило бы весь домен.

## Правила, которые не обсуждаются

- **Числа только из реальных прогонов.** Никаких «экономит до 90%» без замера. Если метрика где-то уходит в минус — сказать это там же, а не прятать.
- **Хук — fail-open.** Любая внутренняя ошибка — тихий `exit 0`, ни при каких обстоятельствах не блокировать старт сессии. Блокировка допустима только намеренная и ограниченная — как у Stop-хука `test-gate` (не больше 2 раз на коммит).
- **Любая запись в предсказуемый путь — symlink-safe.** Отказ, если цель или её родитель — симлинк.
- **Auto-Clarity в любом скилле, который что-то сокращает.** Раздел, где явно сказано, при каких условиях сокращение отключается: security-предупреждения, необратимые действия, многошаговые последовательности, повторный вопрос пользователя.
- **Контракт вывода сабагента фиксирован и грепается.** Вывод сабагента вклеивается в главный контекст дословно, поэтому это бюджет главного окна, а не его собственного.

## Чужие скиллы

Чужое не вендорится — в `domains/` лежит только своё. Чужой скилл ставится в проект своим способом, рядом с нашими; `as-skill` его не отслеживает (`<project>/.claude/skills-lock.json` хранит только то, что поставил сам `as-skill`), `doctor` показывает его как `UNTRACKED`, а `install`/`uninstall` его не трогают.

Заимствованная механика допустима, дословное копирование текста — нет. Если скилл написан по мотивам чужого, атрибуция идёт в его `README.md` строкой «идея: <источник>, <лицензия>».

Коммиты — Conventional Commits, как описано в `domains/git/rules/git-conventions.md`: одна строка-subject без тела и трейлеров, без AI-атрибуции (`Co-Authored-By`, «Generated with …»). Проверить сообщение — `domains/git/skills/git-conventional-commits/scripts/lint-commit-msg.py`.
