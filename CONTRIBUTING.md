# Как править as-skill

Это личная коллекция, но устроена так, чтобы её можно было форкнуть и вести дальше. Ниже — правила, которые держат репозиторий в порядке.

## Один источник правды

Редактируется **только `domains/`** (и `core/skills/` — для скиллов без домена). Никакого сгенерированного зеркала в корне репозитория нет: `.claude/` — гитигнорится и представляет собой не копию, а **symlink-установку** `domains/`/`core/skills/` через инсталлятор `as-skill` — правки под `domains/` видны в ней сразу, без пересборки и без отдельного шага синхронизации. Пересоздать её с нуля, если разъехалась или удалилась:

```bash
rm -rf .claude
./as-skill install domains code git --project .
```

`as-skill install ... --copy` вместо symlink делает независимый снэпшот — этим режимом ставят, например, домен `code` в чужой проект (`as-skill install domain code --project <path> --copy --with-core`). Подробности обоих режимов — в `AGENTS.md` и `tools/README.md`.

## SKILL.md и README.md — разные документы

`SKILL.md` — промпт для модели. Пишется в императиве, содержит алгоритм, границы применимости и раздел «чего не делать». Модель читает его целиком при срабатывании, поэтому лишний текст стоит денег в каждом вызове.

`README.md` рядом — объяснение для человека, который листает GitHub и решает, нужно ему это или нет. Что делает, когда срабатывает, пример до/после.

Не сливай их в один файл и не копируй один в другой.

## Добавление скилла

1. `domains/<домен>/skills/<имя>/SKILL.md` с фронтматтером `name` и `description`.
2. Имя каталога и `name` во фронтматтере должны совпадать — это проверяет `as-skill check`. Префикс домена (`git-`, `obsidian-`, …) в имени — конвенция из `AGENTS.md`, автоматически пока не проверяется, но её всё равно держим.
3. `README.md` рядом.
4. Обнови счётчик скиллов/агентов/правил домена в таблице «Домены» корневого `README.md`.
5. `go build -o as-skill ./tools && ./as-skill check && go test ./...` — собрать, прогнать self-check манифестов и `SKILL.md`, прогнать тесты `tools/`. Если правишь домен, установленный в корневой `.claude/` (сейчас это `code` и `git`), и хочешь увидеть новый скилл там же — `as-skill install` симлинкует записи поштучно, так что новый файл подхватится только после повторного `./as-skill install domains code git --project .`.

`description` — единственное, по чему модель решает, звать скилл или нет. Пиши туда триггерные формулировки живым языком («написать постмортем», «разобрать инцидент»), а не абстрактное описание возможностей. Если два скилла могут сработать на одну фразу — разведи их описания явно, взаимными отсылками.

## Добавление домена

1. `domains/<имя>/{manifest.yaml, rules/, skills/, agents/}` — `rules/` и `skills/` не обязательны (пример — `devops`, пока только `agents/`).
2. В манифесте — `name`, `description`, `requires_env`, `targets`; внешний CLI объявляется через `requires_bin`.
3. Все компоненты домена получают префикс `<имя>-`.
4. Строка в таблице «Домены» корневого `README.md`.

## Требования домена

`requires_env` — переменная окружения. Не задана — `as-skill install all` пропускает домен целиком, с предупреждением; явный `as-skill install domain|domains|skill` по этому домену вместо этого падает с ошибкой.

`requires_bin` — та же логика поверх `exec.LookPath`, для внешнего CLI. Нужна, когда часть домена работает поверх внешнего инструмента, а часть — нет: без неё отсутствие одного бинаря уносило бы весь домен.

## Правила, которые не обсуждаются

- **Числа только из реальных прогонов.** Никаких «экономит до 90%» без замера. Если метрика где-то уходит в минус — сказать это там же, а не прятать.
- **Хук обязан молча падать.** Ни при каких обстоятельствах не блокировать старт сессии.
- **Любая запись в предсказуемый путь — symlink-safe.** Отказ, если цель или её родитель — симлинк.
- **Auto-Clarity в любом скилле, который что-то сокращает.** Раздел, где явно сказано, при каких условиях сокращение отключается: security-предупреждения, необратимые действия, многошаговые последовательности, повторный вопрос пользователя.
- **Контракт вывода сабагента фиксирован и грепается.** Вывод сабагента вклеивается в главный контекст дословно, поэтому это бюджет главного окна, а не его собственного.

## Чужие скиллы

Чужое не вендорится. Если рядом с нашими скиллами живёт чужой — он попадает в `skills-lock.json` с источником, лицензией и sha256, а не в `domains/`.

Заимствованная механика допустима, дословное копирование текста — нет. Если скилл написан по мотивам чужого, атрибуция идёт в его `README.md` строкой «идея: <источник>, <лицензия>».

Коммиты — Conventional Commits, как описано в `domains/git/rules/git-conventions.md`.
