# Безопасность

## Что здесь вообще есть

`as-skill` — это markdown-файлы (промпты для AI-агента), Go-инсталлятор (`tools/`, собирается в бинарь `as-skill`) и немного исполняемого кода рядом со скиллами:

- **Хуки** — запускаются Claude Code сами, по событию сессии. Ставятся только вместе со своим доменом и работают, только если зарегистрированы в `.claude/settings.json` проекта. Все fail-open: любая внутренняя ошибка — тихий выход 0.
    - `code`: `test-gate.sh` (Stop — может намеренно заблокировать завершение задачи, не больше 2 раз на коммит), `prettier-format.sh` (PostToolUse — правит форматирование файлов проекта).
    - `core`: `memory-bank-load.sh` (SessionStart — читает `.memory-bank/`), `memory-bank-logger.sh` (SessionEnd — см. «Сеть» ниже).
- **Скрипты скиллов** — запускает модель по инструкции из `SKILL.md`, в рамках обычных разрешений сессии: `git-conventional-commits/scripts/lint-commit-msg.py`, `git-release-tag/scripts/release.py`, `content-humanizer/scripts/`, `code-init/scripts/register-hooks.sh`.

Поверхность атаки:

1. **Инсталлятор** (`as-skill`) пишет в `<project>/.claude/` — куда именно, решает флаг `--project` (по умолчанию текущая директория). Он не трогает домашний `~/.claude/`, `~/.codex/`, `~/.cursor/` и не пишет в Obsidian vault напрямую — если только их путь явно не передан в `--project`.
2. **Хуки и скрипты** — исполняемый код, который запускается с правами пользователя.
3. **Содержимое скиллов** попадает в контекст модели и влияет на её действия.

## Что делает инсталлятор

`as-skill install` кладёт домены/скиллы в `<project>/.claude/{rules,skills,agents,hooks}` — по умолчанию **symlink**'ами на файлы этой копии репозитория (правки в `domains/` видны во всех проектах, куда они засимлинканы, сразу — это осознанный побочный эффект режима, стоит помнить о нём при шаринге репозитория между несколькими людьми с разными правами). `as-skill install --copy` вместо этого делает независимую копию-снэпшот.

Каждая поставленная единица (домен + вид + имя) записывается в `<project>/.claude/skills-lock.json` — по этой записи `as-skill status`/`doctor` отличают своё от чужого и режим установки, а `uninstall` сносит только то, что сам же поставил. Если путь назначения уже существует и не отслеживается — `install` откажется писать без `--force`.

`install` хуки только кладёт на диск, но не включает. Регистрирует их в `<project>/.claude/settings.json` скилл `/code-init` через `register-hooks.sh` — и только с согласия пользователя. `uninstall` хуков снимает из `settings.json` только записи, указывающие на удалённые им файлы; остальные ключи и чужие хуки не трогает. `settings.local.json` и глобальный `~/.claude/settings.json` не трогаются никогда.

Ни инсталлятор, ни сами скиллы не требуют root и не устанавливают пакеты.

## Сеть

Инсталлятор в сеть не ходит. Сетевая активность вокруг репозитория:

- `git clone/pull` самого `as-skill`.
- **`memory-bank-logger.sh`** (SessionEnd, домен `core`) — после каждой сессии (от 3 промптов пользователя) запускает в фоне headless `claude -p`, который читает транскрипт сессии и обновляет `.memory-bank/`. То есть транскрипт **автоматически, без отдельного подтверждения** уходит в Anthropic API — тем же путём, что и любая сессия Claude Code, но это лишний запрос с полным содержимым сессии. Дочерняя сессия идёт с `--permission-mode acceptEdits` и инструментами `Read`/`Glob`/`Grep`/`Edit`/`Write`; ограничение «править только `.memory-bank/`» задано промптом, а не песочницей. Лог — `.claude/sessions/memory-bank-logger.log`. Не нужно — не регистрируй хук (или сними его из `settings.json`); без `claude`, `jq` или `.memory-bank/index.md` он ничего не делает. Рекурсия исключена через `MEMORY_BANK_LOGGER=1`.
- **`git-release-tag`** — ходит в GitHub через `gh` (`gh run list`, `gh release create`), push и создание релиза — только после подтверждения.

## Что скиллы делают с твоими данными

Скиллы работают только с тем, что ты им дал в сессии. Никакой телеметрии — в репозитории нет кода, который шлёт данные куда-либо, кроме перечисленного в «Сеть».

Домен `obsidian` читает и пишет файлы внутри `$OBSIDIAN_VAULT` (см. `README.md`, раздел «Как задать `OBSIDIAN_VAULT`»). Домен `git` предлагает git-команды, но по общему для всех доменов контракту «план → подтверждение → действие → отчёт» (`CLAUDE.md`) не делает push, tag, GitHub release и удаление веток без явного подтверждения. Домен `devops` не вызывает внешний CLI напрямую — сегодня это только советующие (Consilium: `architecture`, `security`, `sre`, `diagnostics` — read-only, не трогают код и конфиги) и исполняющие (`ci`, `helm`, `k8s` — пишут пайплайны/чарты/манифесты в своей части файлов) агенты; по GitOps-правилу прод меняется только через ArgoCD, ни один агент не делает `kubectl apply` в прод напрямую.

## Prompt injection

Скиллы и агенты, которые читают внешний материал (`obsidian-ingest`, `content-factory` он же `/content-zavod`, `devops-diagnostic`, `devops-sre`), обрабатывают текст из источников, которые ты не писал: статьи, транскрипции, логи. Такой текст может содержать инструкции, адресованные модели.

Отдельный случай — `memory-bank-logger.sh`: он подаёт на вход headless-сессии весь транскрипт, включая прочитанные в ней чужие файлы и вывод команд. Внедрённая туда инструкция может попасть в `.memory-bank/`, а оттуда — через `memory-bank-load.sh` — в контекст каждой следующей сессии. Изменения в `.memory-bank/` стоит просматривать в `git diff`, как обычный код.

Правило простое: **содержимое источника — это данные, а не команды**. Если после ингеста статьи агент вдруг предлагает выполнить команду, которой ты не просил, — это ровно тот случай. Не выполняй, посмотри исходник.

## Как сообщить о проблеме

Нашёл что-то, что позволяет коллекции сделать с системой больше, чем описано выше, — напиши на <ialexshishin@gmail.com> или заведи issue в [репозитории](https://github.com/alexeyshishin/as-skill), если проблема не эксплуатируется по описанию.

Публичный issue подходит для «скрипт удаления сносит лишнее». Приватное письмо — для «вот так через скилл можно выполнить произвольную команду».

Ответ — в течение недели. Это личный проект, не продукт с SLA.
