# as-skill

CLI, который устанавливает домены и скиллы `as-skill` в каталоги платформы целевого проекта (`-a`, по умолчанию автоопределение, иначе `claude` → `.claude/`; см. [Платформы](../README.md#платформы)).

## Сборка

Нужен Go ≥ 1.25. Первая сборка (`go build` или `install.sh`) скачивает зависимости из Go module proxy — один раз нужна сеть; клон без сети и без кэша зависимостей не соберётся. Из корня репозитория (`go.mod` лежит там же, чтобы `domains/` был
достижим):

```bash
go build -o as-skill ./tools
```

или запуск прямо из исходников: `go run ./tools <команда>`.

### `install.sh`

`source install.sh` из корня репозитория собирает `as-skill`, сразу добавляет его в `PATH` текущей оболочки (sh/bash/zsh) и сохраняет PATH для новых терминалов: путь пишется в `~/.config/as-skill/env`, а в rc-файл (`~/.zshrc` для zsh; `~/.bash_profile` и `~/.bashrc` для bash; `~/.profile` иначе) дописывается одна guard-строка без machine-specific пути — безопасно для dotfiles-репозиториев. Уже открытые терминалы подхватят PATH ещё одним `source install.sh`.

Без `source` (`./install.sh`, `bash install.sh`) бинарь соберётся, но в PATH родительской оболочки не попадёт (дочерний процесс так не умеет) — скрипт это видит и подсказывает запустить через `source`. Для новых терминалов PATH сохранится в любом случае.

### Платформы

`as-skill` — обычный Go-бинарь без platform-specific кода: macOS, Linux, Windows.

- **Windows, `install.sh`** — это `sh`-скрипт: запускайте через Git Bash или WSL, либо соберите напрямую: `go build -o as-skill.exe ./tools`.
- **Windows, symlink-режим** — `os.Symlink` требует привилегию `SeCreateSymbolicLinkPrivilege`: нужен включённый **Developer Mode** (Windows 10 1703+ / 11) или терминал **от администратора**. Иначе установка падает с ошибкой прав — ставьте с `--copy` (live-правки из `domains/` тогда не подхватываются, после изменений нужна переустановка).
- **fish** — `install.sh` правит только POSIX rc-файлы и `config.fish` не трогает: определяет это по `$SHELL` и печатает подсказку. Добавьте PATH вручную: `fish_add_path <путь к чекауту as-skill>`.

## Использование

| Команда | Что делает |
|---------|-----------|
| `as-skill add <имя...> [-a P] [-p PATH] [--copy] [-y] [--dry-run]` | поставить домены и/или скиллы. Имя — домен или скилл, определяется автоматически (при совпадении побеждает домен); `all` — все домены, закрытые `requires_env` пропускаются с предупреждением. В терминале без аргументов открывает диалог (см. «Диалог»); без терминала нужны имена и `-y` (или `--dry-run`), иначе — выход с подсказкой, ничего не пишется. По умолчанию symlink, `--copy` — снэпшот |
| `as-skill remove [<имя...>] [-a P] [-p PATH] [-y] [--dry-run]` | снять то, что поставил `add` (без имён в терминале — диалог выбора из lockfile; без терминала нужны имена и `-y`/`--dry-run`): по записям lockfile, работает и без доступной копии репозитория; платформы по умолчанию — все, записанные для проекта. Symlink для link-записей, реальные файлы для copy-записей; чужого/неотслеживаемого не трогает. Для хуков домена заодно убирает их регистрации из `.claude/settings.json` — только записи, указывающие на снятые файлы; остальные ключи и чужие хуки остаются, `settings.local.json` не трогается, `--dry-run` показывает `would unregister`. Скилл, стоящий только как часть copy-домена, снимается вместе с доменом (`remove <домен>`). Без копии репозитория: записи с `items` снимаются полностью, а регистрации хуков и блоки `AGENTS.md` остаются на месте (с предупреждением); старые copy-записи без `items` снять нельзя — команда ничего для них не удаляет, оставляет запись и завершается с ошибкой: переустановите один раз текущим бинарём (`add --copy`) или удалите файлы вручную. Пути вне платформенных каталогов проекта (`.claude`, `.agents`, `.codex`, `.cursor`, `.opencode`) отклоняются, ничего не удаляется |
| `as-skill list [domains\|skills\|platforms]` | показать, что можно поставить; установленное в `-p` проекте (по умолчанию `.`) помечено `installed`; `platforms` — матрица платформ и дата проверки |
| `as-skill doctor [-p PATH] [-a P]` | таблица записей lockfile (домен/вид/имя, режим, платформы, путь, здоровье OK/MISSING/BROKEN) плюс проверки: источник symlink'а пропал (SOURCE-GONE), у copy-записи разошёлся хэш (DRIFTED), на диске есть неотслеживаемое (UNTRACKED), у сгенерированного агента изменился источник (STALE); предупреждения без влияния на exit: DUPLICATE-SKILL, UNVERIFIED, HOOKS-TRUST; ненулевой exit при любой находке — годится как CI gate. Без доступной копии репозитория lint и SOURCE-GONE пропускаются с пометкой |

Продвинутые:

| Команда | Что делает |
|---------|-----------|
| `as-skill hooks enable\|disable [<имя>...\|all] [-d D[,D]] -a P` | зарегистрировать/снять хуки в `.claude/settings.json`, `.codex/hooks.json`, `.cursor/hooks.json`; чужие записи не трогает; с `--domain` имена берутся из исходников доменов (без имён/`all` — все регистрируемые хуки домена на платформе), `enable --dry-run --domain` печатает `would register` без установленных файлов; без `--domain` имена читаются из `.<платформа>/hooks` проекта; codex/cursor — по документации, не проверено на реальных CLI |
| `as-skill check` | валидирует `domains/*/manifest.yaml` и `skills/*/SKILL.md` в копии репозитория; имена скиллов уникальны между доменами, не равны имени домена и `all`; без `-p` |

Копия репозитория находится автоматически: `--harness-root` → вверх от текущей директории → вверх от реального пути бинаря. Бинарь, собранный в чекауте, работает из любого проекта. `-p` — проект, который вы оснащаете.

### Диалог

Открывается, если stdin и stderr — терминал, `CI` не задан и `TERM` не `dumb`. `as-skill add` без аргументов спрашивает по шагам:

Подсказки на английском. `shift+tab` — назад к предыдущему шагу (пропуская заданные заранее и шаги без вопроса; на первом шаге ничего не делает), прежние ответы остаются значениями по умолчанию (в том числе выбор скиллов и решения по конфликтам).

1. «Project directory» — по умолчанию абсолютный cwd; `~` раскрывается, путь должен существовать, `$HOME` отклоняется;
2. «Domains to add» — мультивыбор без предвыбора, нужен хотя бы один; метка `name — description (needs $VAR) [installed]`: установленные помечены `[installed]`, закрытые `requires_env` подписаны и отклоняются, пока переменная не задана;
3. «Customize skills?» — Confirm, по умолчанию No; спрашивается после выбора доменов (в том числе заданных именами), если у выбранных доменов есть скиллы. Yes → по мультивыбору «Skills to install from <домен>» на каждый домен: все скиллы предвыбраны, снятые не ставятся (ключ `домен/скилл`), правила, агенты и хуки домена ставятся как обычно. Только в диалоге: `-y` не спрашивает и ничего не исключает, отдельно названные скиллы (`add caveman`) не настраиваются. Снять все скиллы домена нельзя: пустой выбор отклоняется сообщением `select at least one skill; to skip a domain's skills entirely, don't choose the domain` — чтобы пропустить скиллы домена целиком, не выбирайте домен. То же для любого мультивыбора с предвыбором (платформы, скиллы): снять всё и нажать Enter — ошибка валидации; Enter на пустом списке без предвыбора (домены) берёт подсвеченный пункт;
4. «Platforms» — всегда все четыре (claude, codex, cursor, opencode); у автоопределённых предвыбор и пометка ` (detected)`; если ничего не найдено, предвыбран `claude` без пометки; платформа, чьи link-каталоги в git-репозитории не в `.gitignore`, помечена `[.cursor not git-ignored]` (в symlink-режиме её установка будет отклонена). Режим спрашивается позже платформ, поэтому пометка учитывает только заранее заданные флаги: при `--copy` или `--force` она не показывается;
5. «Install mode» — `symlink — …` (по умолчанию) или `copy — …`;
6. конфликты — после режима, до сводки: диалог прогоняет установку «вхолостую» (`Installer.PlanInstall`: ничего не пишет, ничего не печатает) и показывает найденное в два класса:
   - каталоги не в `.gitignore` (link-режим) — по Select на каждую затронутую платформу, `guard:<платформа>`: `drop platform <имя>` (по умолчанию: платформа убирается из списка, выбранный symlink-режим остальных платформ сохраняется; если платформа единственная, `drop` равен `abort` — `aborted`, поэтому по умолчанию выбран `copy`) / `switch ALL platforms to copy` (режим один на запуск, поэтому копия включается для всех платформ, в том числе тех, что были выбраны с symlink; сводка это показывает строкой `adjusted:`) / `abort`. Ранее сделанный выбор (возврат назад) сильнее значения по умолчанию. После каждого решения прогон повторяется, пока конфликтов не останется;
   - существующие чужие (неотслеживаемые) пути — один Confirm `Overwrite these N paths?` со списком путей, по умолчанию No. Yes → перезаписываются ровно эти пути (`Installer.Overwrite`; флаг `--force` диалог не включает), No → `aborted`, ничего не записано;
   
   Зарезервированные имена агентов и прочие ошибки установки — не вопрос, а жёсткая ошибка до записи;
7. «Hooks to register» (id `hooks`) — после конфликтов, до сводки: мультивыбор хуков выбранных доменов, метка `name — Event (платформы регистрации)`, **по умолчанию ничего** (Enter без выбора = не регистрировать). Регистрируемый хук — `domains/<d>/hooks/*.sh` со строкой `# register:` (`test-gate-lib.sh` — библиотека, не регистрируется). Шаг пропускается, если у выбранных доменов нет таких хуков или ни одна итоговая платформа не поддерживает хуки с учётом `# platforms:` хука (например только opencode). Регистрация — после установки и записи lockfile, только выбранных хуков и только на платформах из `# platforms:` (test-gate, prettier-format, memory-bank-load — claude/codex/cursor; test-gate-record — codex/cursor; memory-bank-logger — только claude): `.claude/settings.json`, `.codex/hooks.json`, `.cursor/hooks.json`. `memory-bank-logger` несёт предупреждение: транскрипт сессии уходит в API, запускается фоновая `claude -p` с acceptEdits; в сводке — строка `warning:`. `-y` и любой запуск без диалога хуки **никогда** не регистрирует (файлы кладутся как раньше); флага для заранее заданного ответа нет. `--dry-run` в диалоге: вопрос задаётся, затем печатается `would register <name> (<Event>) in <path>` по `# register:` исходников, ничего не пишется, пустой проект допустим. Размещение файлов хуков не меняется; `hooks enable|disable` и `/code-init` работают по-прежнему;
8. сводка и «Install?» (по умолчанию Yes; у `remove` — «Remove?»). Строки сводки: `harness:`, `warning:` (checkout в cwd ≠ checkout бинаря), `project:`, `domains:`/`skills:`, при исключениях `deselect:  домен/скилл, …` и `warning:   agents may reference deselected skills` (агенты могут ссылаться на снятые скиллы), для снятых, но уже стоящих (по lockfile; чужой неотслеживаемый каталог не считается) скиллов — `warning:   домен/скилл: already installed, deselected, kept — use remove` (установленное не удаляется молча, исключения нигде не сохраняются), `platforms: … (detected from X | default | -a)`, `adjusted:` (смена режима, снятая платформа, перезапись путей), предупреждения о пробелах возможностей платформ и о дублях скиллов, `hooks: none|<имена>` (и `warning:` при `memory-bank-logger`), `mode:`. Отказ или Ctrl-C — ничего не пишется, `as-skill: error: aborted`, код выхода 1.

Имена и флаги заранее отвечают на свой вопрос: имена пропускают выбор доменов, `-a` — платформы, `-p` — проект, `--copy` — режим; `-y` берёт все значения по умолчанию без вопросов. `as-skill` без глагола по-прежнему печатает help.

`as-skill remove` без аргументов в терминале: мультивыбор установленных доменов и отдельных скиллов из lockfile; вопрос о платформах — только если в lockfile записано больше одной; затем сводка и подтверждение.

Диалог требует терминал и на stdin, и на stderr: `as-skill add git | cat` (в pipe только stdout) его всё равно откроет. При `</dev/null`, `2>файл`, заданном `CI` или `TERM=dumb` поведение прежнее: нужны имена и `-y` (или `--dry-run`), иначе выход с подсказкой.

### Legacy

Старые формы работают, но скрыты из help: `install domain|domains|all|skill ...`, `uninstall ...`, `status` (только таблица, exit 0) и флаги `--platform`, `--force`, `--harness-root`. Пишущие `install`/`uninstall` и `hooks enable|disable` отклоняют `-p`, равный `$HOME` (тем же текстом, что `add`); остальная обработка пути прежняя; `status` только читает и не ограничен.

## Пакеты

`internal/`: `cli` (диспетчер, разбор флагов на `spf13/pflag`; напрямую импортирует `doctor`, `harness`, `install`, `lint`, `fsys`, `iostreams`, `lockfile`, `platform`, `prompt`); `doctor`, `lint`, `install` опираются на `harness`; `install` ещё на `render` и `hookcfg`; `render` импортирует `lockfile` и `platform`, `hookcfg` — только `platform`; `harness` — `frontmatter`, `fsys`, `lockfile`; листья `platform`, `lockfile`, `fsys`, `frontmatter`, `iostreams`; плюс `hooktest` (тесты хуков).

## Флаги

Общие для `add`/`remove`, если не указано иное:

| Флаг | Что делает | По умолчанию |
|------|-----------|--------------|
| `-p, --project PATH` | корень целевого проекта: `~` раскрывается, путь должен существовать, `$HOME` отклоняется | `.` |
| `-d, --domain D` | только `hooks`: домены (через запятую или повтором), из исходников которых берутся хуки | — |
| `-a, --agent P` | `claude\|codex\|cursor\|opencode\|all`, через запятую или повтором; также для `doctor`/`hooks` | автоопределение (ниже) |
| `--copy` | только `add`: копия-снэпшот вместо symlink | выключено (по умолчанию — symlink) |
| `-y` | принять значения по умолчанию: никаких вопросов и подтверждений (обязателен без терминала, если нет `--dry-run`) | выключено |
| `--dry-run` | ничего не пишет, только печатает план | выключено |

Платформа по умолчанию определяется по существующим `.codex/`, `.cursor/`, `.opencode/`, `.claude/` (если там не один только `skills-lock.json`) и платформам, записанным в lockfile; ничего нет — `claude`. Вывод печатает источник (`platforms: detected from ...`). Если у обнаруженной платформы link-каталог не в `.gitignore`, `add -y` падает до записи и подсказывает `-a claude` или `--copy`. То же для любого конфликта вообще (в том числе при явном `-a`, для чужих неотслеживаемых путей и для списка из нескольких скиллов): `add -y` заранее прогоняет установку вхолостую, и при первом же конфликте завершается ошибкой с подсказкой (`-a claude`, `--copy` или убрать пути), не записав ничего.

Link-режим для `.agents`, `.codex`, `.cursor`, `.opencode` внутри git-репозитория требует, чтобы каталог был в `.gitignore` (`git check-ignore`); иначе отказ — добавьте каталог или ставьте `--copy` (`--force` обходит).

Если `manifest.yaml` домена в `requires_env` называет неустановленную
переменную (сегодня это только `obsidian` → `$OBSIDIAN_VAULT`) — жёсткая
ошибка для явно названного домена/скилла и предупреждение + пропуск для
`all`. Есть и зеркальный `requires_bin` (проверяется через `$PATH`), но
сегодня его не объявляет ни один домен.
