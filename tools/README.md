# as-skill

CLI-тул, который устанавливает домены и скиллы `claude-harness` в директорию
`.claude/` целевого проекта. Режим по умолчанию — symlink (для совместной
разработки: правки в `domains/`/`core/skills/` видны в проекте сразу, без
переустановки); `--copy` переключает на статический снэпшот (для шаринга или
проектов, которые не должны зависеть от жизненного цикла этой копии
репозитория) — так работает, например, скилл `/code-setup` домена `code`,
который явно передаёт `--copy` при установке себя в чужой проект.

## Сборка

Из корня репозитория (`go.mod` лежит там же, чтобы `domains/` и `core/` были
достижимы):

```bash
go build -o as-skill ./tools
```

или запуск прямо из исходников: `go run ./tools <команда>`.

## Использование

```
as-skill install domain  <имя>               symlink один домен (режим по умолчанию)
as-skill install domains <имя> [имя...]      symlink несколько доменов
as-skill install all                          symlink все домены + core-скиллы
as-skill install skill   <имя>               symlink один скилл (доменный или core)
as-skill install ... --copy                   вместо symlink — копия-снэпшот
                                               (те же формы аргументов, что выше)
as-skill uninstall domain|domains|all|skill ... удалить то, что поставил install
                                               (symlink для link-записей, реальные
                                               файлы/директории для copy-записей;
                                               чужого/неотслеживаемого не трогает)
as-skill status [--project PATH]              список записей lockfile: домен/вид/
                                               имя, режим, путь, здоровье
                                               (OK/MISSING/BROKEN)
as-skill doctor [--project PATH]
                [--harness-root PATH]         то же, что status, плюс проверки:
                                               источник symlink'а пропал, у copy-
                                               записи разошёлся хэш (DRIFTED),
                                               на диске есть неотслеживаемое
                                               (UNTRACKED); ненулевой exit при
                                               любой находке — годится как CI gate
as-skill check                                валидирует domains/*/manifest.yaml
                                               и skills/*/SKILL.md в этой копии
                                               репозитория; без --project
as-skill list [domains|skills]                показать, что можно установить
```

Флаги (`install`/`uninstall`): `--project PATH` (корень целевого проекта, по
умолчанию `.`), `--harness-root PATH` (эта копия репозитория, по умолчанию —
автоопределяется вверх от `.`), `--with-core` (доустановить/удалить
`core/skills/*` вместе с `domain`/`domains`/`skill` — у `all` они всегда
включены), `--copy` (только `install`: копия-снэпшот вместо symlink),
`--dry-run` (ничего не пишет, только печатает план), `--force` (только
`install`: перезаписать существующее в целевом пути, даже если as-skill его
не отслеживает — по умолчанию это отказ).

`as-skill` должен запускаться изнутри (или из поддиректории) копии
`claude-harness`, либо с явным `--harness-root` — он читает
`domains/*/manifest.yaml` и `core/skills/*` оттуда. `--project` — независимый
путь: проект, который вы оснащаете.

Если `manifest.yaml` домена в `requires_env` называет неустановленную
переменную (сегодня это только `obsidian` → `$OBSIDIAN_VAULT`) — это
**жёсткая ошибка** для явного запроса `domain`/`domains`/`skill`, и
**предупреждение + пропуск** (остальное всё равно ставится) для `all` —
поведение соответствует тому, что уже описано в AGENTS.md. Есть и зеркальный
ключ `requires_bin` — тот же формат списка, что и `requires_env`, но
проверяется через `exec.LookPath` (бинарь есть в `$PATH`); механизм уже
реализован и подчиняется тем же правилам strict/warn, но сегодня его не
объявляет ни один домен.

Повторный запуск идемпотентен: перезаписывает то, что сам же поставил
(symlink переставляется, копия перезаписывается файл за файлом), и никогда
не трогает то, что уже лежит в `.claude/` из других источников — если путь
назначения существует и as-skill его не отслеживает, `install` откажется
без `--force`.

### Lockfile

Каждый install/uninstall пишет и читает `<project>/.claude/skills-lock.json` —
по одной записи на каждую поставленную единицу (домен+вид+имя, режим `link`
или `copy`, путь, источник, для copy — SHA256 дерева). Это позволяет
отличать «своё» (поставлено as-skill) от «чужого» (руками положено в
`.claude/`), различать режим установки при смешанных link/copy-сессиях в
одном проекте, и по этой же записи `status`/`doctor` определяют здоровье
записи, а `uninstall` — что можно снести, а что нет.
