# as-skill

CLI, который устанавливает домены и скиллы `as-skill` в каталоги платформы целевого проекта (`-a`, по умолчанию автоопределение, иначе `claude` → `.claude/`; см. [Платформы](../README.md#платформы)).

## Сборка

Нужен Go ≥ 1.25. Первая сборка (`go build` или `install.sh`) скачивает зависимости из Go module proxy — один раз нужна сеть; клон без сети и без кэша зависимостей не соберётся. Из корня репозитория (`go.mod` лежит там же, чтобы `domains/` был
достижим):

```bash
go build -o as-skill ./tools
```

или запуск прямо из исходников: `go run ./tools <команда>`.

### `install.sh`

`source install.sh` из корня репозитория собирает `as-skill`, сразу добавляет его в `PATH` текущей оболочки (sh/bash/zsh) и сохраняет PATH для новых терминалов: путь пишется в `~/.config/as-skill/env`, а в rc-файл (`~/.zshrc` для zsh; `~/.bash_profile` и `~/.bashrc` для bash; `~/.profile` иначе) дописывается одна guard-строка без machine-specific пути — безопасно для dotfiles-репозиториев. Уже открытые терминалы подхватят PATH ещё одним `source install.sh`.

Без `source` (`./install.sh`, `bash install.sh`) бинарь соберётся, но в PATH родительской оболочки не попадёт (дочерний процесс так не умеет) — скрипт это видит и подсказывает запустить через `source`. Для новых терминалов PATH сохранится в любом случае.

### Платформы

`as-skill` — обычный Go-бинарь без platform-specific кода: macOS, Linux, Windows.

- **Windows, `install.sh`** — это `sh`-скрипт: запускайте через Git Bash или WSL, либо соберите напрямую: `go build -o as-skill.exe ./tools`.
- **Windows, symlink-режим** — `os.Symlink` требует привилегию `SeCreateSymbolicLinkPrivilege`: нужен включённый **Developer Mode** (Windows 10 1703+ / 11) или терминал **от администратора**. Иначе установка падает с ошибкой прав — ставьте с `--copy` (live-правки из `domains/` тогда не подхватываются, после изменений нужна переустановка).
- **fish** — `install.sh` правит только POSIX rc-файлы и `config.fish` не трогает: определяет это по `$SHELL` и печатает подсказку. Добавьте PATH вручную: `fish_add_path <путь к чекауту as-skill>`.

## Использование

| Команда | Что делает |
|---------|-----------|
| `as-skill add <имя...> [-a P] [-p PATH] [--copy] [-y] [--dry-run]` | поставить домены и/или скиллы. Имя — домен или скилл, определяется автоматически (при совпадении побеждает домен); `all` — все домены, закрытые `requires_env` пропускаются с предупреждением. В терминале без аргументов открывает диалог (см. «Диалог»); без терминала нужны имена и `-y` (или `--dry-run`), иначе — выход с подсказкой, ничего не пишется. По умолчанию symlink, `--copy` — снэпшот |
| `as-skill remove [<имя...>] [-a P] [-p PATH] [-y] [--dry-run]` | снять то, что поставил `add` (без имён в терминале — диалог выбора из lockfile; без терминала нужны имена и `-y`/`--dry-run`): по записям lockfile, работает и без доступной копии репозитория; платформы по умолчанию — все, записанные для проекта. Symlink для link-записей, реальные файлы для copy-записей; чужого/неотслеживаемого не трогает. Для хуков домена заодно убирает их регистрации из `.claude/settings.json` — только записи, указывающие на снятые файлы; остальные ключи и чужие хуки остаются, `settings.local.json` не трогается, `--dry-run` показывает `would unregister`. Скилл, стоящий только как часть copy-домена, снимается вместе с доменом (`remove <домен>`). Без копии репозитория: записи с `items` снимаются полностью, а регистрации хуков и блоки `AGENTS.md` остаются на месте (с предупреждением); старые copy-записи без `items` снять нельзя — команда ничего для них не удаляет, оставляет запись и завершается с ошибкой: переустановите один раз текущим бинарём (`add --copy`) или удалите файлы вручную. Пути вне платформенных каталогов проекта (`.claude`, `.agents`, `.codex`, `.cursor`, `.opencode`) отклоняются, ничего не удаляется |
| `as-skill list [domains\|skills\|platforms]` | показать, что можно поставить; установленное в `-p` проекте (по умолчанию `.`) помечено `installed`; `platforms` — матрица платформ и дата проверки |
| `as-skill doctor [-p PATH] [-a P]` | таблица записей lockfile (домен/вид/имя, режим, платформы, путь, здоровье OK/MISSING/BROKEN) плюс проверки: источник symlink'а пропал (SOURCE-GONE), у copy-записи разошёлся хэш (DRIFTED), на диске есть неотслеживаемое (UNTRACKED), у сгенерированного агента изменился источник (STALE); предупреждения без влияния на exit: DUPLICATE-SKILL, UNVERIFIED, HOOKS-TRUST; ненулевой exit при любой находке — годится как CI gate. Без доступной копии репозитория lint и SOURCE-GONE пропускаются с пометкой |

Продвинутые:

| Команда | Что делает |
|---------|-----------|
| `as-skill hooks enable\|disable <имя\|all> -a P` | зарегистрировать/снять хуки в `.claude/settings.json`, `.codex/hooks.json`, `.cursor/hooks.json`; чужие записи не трогает; codex/cursor — по документации, не проверено на реальных CLI |
| `as-skill check` | валидирует `domains/*/manifest.yaml` и `skills/*/SKILL.md` в копии репозитория; имена скиллов уникальны между доменами, не равны имени домена и `all`; без `-p` |

Копия репозитория находится автоматически: `--harness-root` → вверх от текущей директории → вверх от реального пути бинаря. Бинарь, собранный в чекауте, работает из любого проекта. `-p` — проект, который вы оснащаете.

### Диалог

Открывается, если stdin и stderr — терминал, `CI` не задан и `TERM` не `dumb`. `as-skill add` без аргументов спрашивает по шагам:

Подсказки на английском. `shift+tab` — назад к предыдущему шагу (пропуская заданные заранее; на первом шаге ничего не делает), прежние ответы остаются значениями по умолчанию.

1. «Project directory» — по умолчанию абсолютный cwd; `~` раскрывается, путь должен существовать, `$HOME` отклоняется;
2. «Domains to add» — мультивыбор без предвыбора, нужен хотя бы один; метка `name — description (needs $VAR) [installed]`: установленные помечены `[installed]`, закрытые `requires_env` подписаны и отклоняются, пока переменная не задана;
3. «Platforms» — всегда все четыре (claude, codex, cursor, opencode); у автоопределённых предвыбор и пометка ` (detected)`; если ничего не найдено, предвыбран `claude` без пометки;
4. «Install mode» — `symlink — …` (по умолчанию) или `copy — …`;
5. сводка и «Install?» (по умолчанию Yes; у `remove` — «Remove?»). Строки сводки: `harness:`, `warning:` (checkout в cwd ≠ checkout бинаря), `project:`, `domains:`/`skills:`, `platforms: … (detected from X | default | -a)`, предупреждения о пробелах возможностей платформ и о дублях скиллов, `mode:`. Отказ или Ctrl-C — ничего не пишется, `as-skill: error: aborted`, код выхода 1.

Имена и флаги заранее отвечают на свой вопрос: имена пропускают выбор доменов, `-a` — платформы, `-p` — проект, `--copy` — режим; `-y` берёт все значения по умолчанию без вопросов. `as-skill` без глагола по-прежнему печатает help.

`as-skill remove` без аргументов в терминале: мультивыбор установленных доменов и отдельных скиллов из lockfile; вопрос о платформах — только если в lockfile записано больше одной; затем сводка и подтверждение.

Диалог требует терминал и на stdin, и на stderr: `as-skill add git | cat` (в pipe только stdout) его всё равно откроет. При `</dev/null`, `2>файл`, заданном `CI` или `TERM=dumb` поведение прежнее: нужны имена и `-y` (или `--dry-run`), иначе выход с подсказкой.

### Legacy

Старые формы работают, но скрыты из help: `install domain|domains|all|skill ...`, `uninstall ...`, `status` (только таблица, exit 0) и флаги `--platform`, `--force`, `--harness-root`.

## Флаги

Общие для `add`/`remove`, если не указано иное:

| Флаг | Что делает | По умолчанию |
|------|-----------|--------------|
| `-p, --project PATH` | корень целевого проекта: `~` раскрывается, путь должен существовать, `$HOME` отклоняется | `.` |
| `-a, --agent P` | `claude\|codex\|cursor\|opencode\|all`, через запятую или повтором; также для `doctor`/`hooks` | автоопределение (ниже) |
| `--copy` | только `add`: копия-снэпшот вместо symlink | выключено (по умолчанию — symlink) |
| `-y` | принять значения по умолчанию: никаких вопросов и подтверждений (обязателен без терминала, если нет `--dry-run`) | выключено |
| `--dry-run` | ничего не пишет, только печатает план | выключено |

Платформа по умолчанию определяется по существующим `.codex/`, `.cursor/`, `.opencode/`, `.claude/` (если там не один только `skills-lock.json`) и платформам, записанным в lockfile; ничего нет — `claude`. Вывод печатает источник (`platforms: detected from ...`). Если у обнаруженной платформы link-каталог не в `.gitignore`, `add -y` падает до записи и подсказывает `-a claude` или `--copy`.

Link-режим для `.agents`, `.codex`, `.cursor`, `.opencode` внутри git-репозитория требует, чтобы каталог был в `.gitignore` (`git check-ignore`); иначе отказ — добавьте каталог или ставьте `--copy` (`--force` обходит).

Если `manifest.yaml` домена в `requires_env` называет неустановленную
переменную (сегодня это только `obsidian` → `$OBSIDIAN_VAULT`) — жёсткая
ошибка для явно названного домена/скилла и предупреждение + пропуск для
`all`. Есть и зеркальный `requires_bin` (проверяется через `$PATH`), но
сегодня его не объявляет ни один домен.
