# as-skill

CLI-тул, который устанавливает домены и скиллы `claude-harness` в директорию
`.claude/` целевого проекта. Работает копированием (снэпшот, не symlink) —
так же, как скилл `/code-setup` домена `code` уже устанавливает себя в
проект.

## Сборка

Из корня репозитория (`go.mod` лежит там же, чтобы `domains/` и `core/` были
достижимы):

```bash
go build -o as-skill ./tools
```

или запуск прямо из исходников: `go run ./tools <команда>`.

## Использование

```
as-skill install domain  <имя>               установить один домен
as-skill install domains <имя> [имя...]      установить несколько доменов
as-skill install all                          установить все домены + core-скиллы
as-skill install skill   <имя>               установить один скилл (доменный или core)
as-skill list [domains|skills]                показать, что можно установить
```

Флаги (только для `install`): `--project PATH` (корень целевого проекта, по
умолчанию `.`), `--harness-root PATH` (эта копия репозитория, по умолчанию —
автоопределяется вверх от `.`), `--with-core` (доустановить `core/skills/*`
вместе с `domain`/`domains`/`skill` — у `all` они устанавливаются всегда),
`--dry-run`.

`as-skill` должен запускаться изнутри (или из поддиректории) копии
`claude-harness`, либо с явным `--harness-root` — он читает
`domains/*/manifest.yaml` и `core/skills/*` оттуда. `--project` — независимый
путь: проект, который вы оснащаете.

Если `manifest.yaml` домена в `requires_env` называет неустановленную
переменную (сегодня это только `obsidian` → `$OBSIDIAN_VAULT`) — это
**жёсткая ошибка** для явного запроса `domain`/`domains`/`skill`, и
**предупреждение + пропуск** (остальное всё равно ставится) для `all` —
поведение соответствует тому, что уже описано в AGENTS.md.

Повторный запуск идемпотентен: перезаписывает файлы, которые сам же поставил,
и никогда не трогает то, что уже лежит в `.claude/` из других источников.
