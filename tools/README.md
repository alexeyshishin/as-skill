# as-skill

CLI, который устанавливает домены и скиллы `as-skill` в каталоги платформы целевого проекта (`-a`, по умолчанию автоопределение, иначе `claude` → `.claude/`; см. [Платформы](../README.md#платформы)).

## Сборка

Нужен Go ≥ 1.25. Первая сборка (`go build` или `install.sh`) скачивает зависимости из Go module proxy — один раз нужна сеть; клон без сети и без кэша зависимостей не соберётся. Из корня репозитория (`go.mod` лежит там же, чтобы `domains/` был
достижим):

```bash
go build -o as-skill ./tools
```

или запуск прямо из исходников: `go run ./tools <команда>`.

### `install.sh`

`source install.sh` из корня репозитория собирает `as-skill`, добавляет его в `PATH` текущей оболочки (sh/bash/zsh) и сохраняет для новых терминалов: путь пишется в `~/.config/as-skill/env`, в rc-файл (`~/.zshrc`; `~/.bash_profile` и `~/.bashrc`; иначе `~/.profile`) — одна guard-строка без machine-specific пути, безопасно для dotfiles-репозиториев. Открытые терминалы подхватят PATH повторным `source install.sh`.

Без `source` (`./install.sh`) бинарь соберётся, но PATH родительской оболочки не изменится — скрипт подскажет запустить через `source`.

### Платформы

`as-skill` — обычный Go-бинарь без platform-specific кода: macOS, Linux, Windows.

- **Windows, `install.sh`** — это `sh`-скрипт: запускайте через Git Bash или WSL, либо соберите напрямую: `go build -o as-skill.exe ./tools`.
- **Windows, symlink-режим** — `os.Symlink` требует привилегию `SeCreateSymbolicLinkPrivilege`: нужен включённый **Developer Mode** (Windows 10 1703+ / 11) или терминал **от администратора**. Иначе установка падает с ошибкой прав — ставьте с `--copy` (live-правки из `domains/` тогда не подхватываются, после изменений нужна переустановка).
- **fish** — `install.sh` правит только POSIX rc-файлы и `config.fish` не трогает: определяет это по `$SHELL` и печатает подсказку. Добавьте PATH вручную: `fish_add_path <путь к чекауту as-skill>`.

## Использование

| Команда | Что делает |
|---------|-----------|
| `as-skill add <имя...> [-a P] [-p PATH] [--copy] [-y] [--dry-run]` | Ставит домены и/или скиллы. Имя — домен или скилл (при совпадении побеждает домен); `all` — все домены, закрытые `requires_env` пропускаются с предупреждением. Без аргументов в терминале — диалог; без терминала нужны имена и `-y` (или `--dry-run`). По умолчанию symlink, `--copy` — снэпшот |
| `as-skill remove [<имя...>] [-a P] [-p PATH] [-y] [--dry-run]` | Снимает то, что поставил `add`, по записям lockfile (копия репозитория не нужна). Чужое и неотслеживаемое не трогает. Регистрации хуков снятого домена убирает из `.claude/settings.json`; `settings.local.json` не трогается. Скилл из copy-домена снимается вместе с доменом. Без копии репозитория регистрации хуков и блоки `AGENTS.md` остаются (с предупреждением). Старые copy-записи без `items` снять нельзя — переустановите (`add --copy`) или удалите файлы вручную. Пути вне каталогов платформ отклоняются |
| `as-skill list [domains\|skills\|platforms]` | Что можно поставить; установленное в проекте `-p` помечено `installed`; `platforms` — матрица платформ |
| `as-skill doctor [-p PATH] [-a P]` | Таблица записей lockfile (режим, платформы, путь, здоровье OK/MISSING/BROKEN) и проверки: SOURCE-GONE, DRIFTED, UNTRACKED, STALE. Предупреждения без влияния на exit: DUPLICATE-SKILL, UNVERIFIED, HOOKS-TRUST. Ненулевой exit при любой находке — годится для CI. Без копии репозитория lint и SOURCE-GONE пропускаются |

Примеры:

```bash
as-skill add all -y                                  # все домены, symlink
as-skill add code core -p <path> --copy -y           # code в чужой проект, снэпшот
as-skill add git core -p <path> -a codex,cursor -y   # другие платформы
as-skill list                                        # что можно поставить
as-skill doctor -p <path>                            # что стоит и в каком состоянии
as-skill remove code -p <path> -y                    # снять
```

Режимы: **symlink** (по умолчанию) — правки в `domains/` видны в проекте сразу, так живёт корневой `.claude/` этого репозитория (см. [`CONTRIBUTING.md`](../CONTRIBUTING.md)); **`--copy`** — статический снэпшот, не зависит от чекаута.

Продвинутые:

| Команда | Что делает |
|---------|-----------|
| `as-skill hooks enable\|disable [<имя>...\|all] [-d D[,D]] -a P` | Регистрирует/снимает хуки в `.claude/settings.json`, `.codex/hooks.json`, `.cursor/hooks.json`; чужие записи не трогает. С `--domain` имена берутся из исходников доменов, `enable --dry-run --domain` печатает `would register`; без `--domain` — из `.<платформа>/hooks` проекта. Codex/cursor — по документации, не проверено |
| `as-skill check` | Валидирует `domains/*/manifest.yaml` и `skills/*/SKILL.md`; имена скиллов уникальны между доменами и не равны имени домена и `all` |

Копия репозитория находится автоматически: `--harness-root` → вверх от cwd → вверх от реального пути бинаря. Бинарь, собранный в чекауте, работает из любого проекта. `-p` — проект, который вы оснащаете.

### Диалог

Открывается, если stdin и stderr — терминалы, `CI` не задан и `TERM` не `dumb` (`add git | cat` его тоже откроет). Иначе нужны имена и `-y` (или `--dry-run`), иначе выход с подсказкой. Подсказки на английском. `shift+tab` — шаг назад (заданные заранее шаги пропускаются), прежние ответы остаются значениями по умолчанию.

Имена и флаги заранее отвечают на свой вопрос (имена — домены, `-a` — платформы, `-p` — проект, `--copy` — режим); `-y` берёт все значения по умолчанию.

1. **Project directory** — по умолчанию cwd; `~` раскрывается, путь должен существовать, `$HOME` отклоняется.
2. **Domains to add** — мультивыбор без предвыбора, нужен хотя бы один. Метка `name — description (needs $VAR) [installed]`; закрытые `requires_env` отклоняются, пока переменная не задана.
3. **Customize skills?** — Confirm, по умолчанию No, если у выбранных доменов есть скиллы. Yes → мультивыбор «Skills to install from <домен>», все предвыбраны; правила, агенты и хуки домена ставятся как обычно. Только в диалоге: `-y` ничего не исключает, отдельно названные скиллы не настраиваются. Пустой выбор отклоняется — чтобы пропустить скиллы домена целиком, не выбирайте домен.
4. **Platforms** — все четыре; у автоопределённых предвыбор и пометка `(detected)`, иначе предвыбран `claude`. Платформа, чей link-каталог не в `.gitignore`, помечена `[.cursor not git-ignored]` (в symlink-режиме будет отклонена); при `--copy` или `--force` пометки нет.
5. **Install mode** — `symlink` (по умолчанию) или `copy`.
6. **Конфликты** — диалог прогоняет установку вхолостую (`Installer.PlanInstall`) и спрашивает:
   - каталог не в `.gitignore` (link-режим) — Select на платформу: `drop platform <имя>` (по умолчанию; для единственной платформы равен `abort`, поэтому по умолчанию `copy`) / `switch ALL platforms to copy` (режим один на запуск; сводка покажет `adjusted:`) / `abort`. После каждого решения прогон повторяется;
   - чужие неотслеживаемые пути — Confirm `Overwrite these N paths?`, по умолчанию No. Yes → перезаписываются ровно эти пути (`--force` диалог не включает), No → `aborted`.

   Зарезервированные имена агентов и прочие ошибки — жёсткая ошибка до записи.
7. **Hooks to register** (id `hooks`) — мультивыбор хуков выбранных доменов, метка `name — Event (платформы)`, **по умолчанию ничего**. Хук — `domains/<d>/hooks/*.sh` со строкой `# register:` (`test-gate-lib.sh` — библиотека). Шаг пропускается, если таких хуков нет или ни одна платформа их не поддерживает. Регистрация — после установки и записи lockfile, на платформах из `# platforms:` хука (test-gate, prettier-format, memory-bank-load — claude/codex/cursor; test-gate-record — codex/cursor; memory-bank-logger — только claude). `memory-bank-logger` несёт предупреждение: транскрипт сессии уходит в API, фоновая `claude -p` работает с acceptEdits. `-y` и запуск без диалога хуки **не** регистрируют. С `--dry-run` вопрос задаётся, затем печатается `would register <name> (<Event>) in <path>`.
8. **Сводка и «Install?»** (по умолчанию Yes; у `remove` — «Remove?»). Строки: `harness:`, `project:`, `domains:`/`skills:`, `deselect:`, `platforms:`, `adjusted:`, `hooks:`, `mode:`, плюс `warning:` — checkout в cwd ≠ checkout бинаря; агенты могут ссылаться на снятые скиллы; снятый скилл уже установлен и сохранён (`use remove`); пробелы возможностей платформ и дубли скиллов; `memory-bank-logger`. Отказ или Ctrl-C — ничего не пишется, `as-skill: error: aborted`, exit 1.

`as-skill remove` без аргументов в терминале: мультивыбор установленных доменов и скиллов из lockfile; платформы спрашиваются, только если в lockfile их больше одной; затем сводка и подтверждение.

### Legacy

Скрыты из help: `install domain|domains|all|skill ...`, `uninstall ...`, `status` (только таблица, exit 0) и флаги `--platform`, `--force`, `--harness-root`. `install`/`uninstall` и `hooks enable|disable` отклоняют `-p`, равный `$HOME`; `status` только читает и не ограничен.

## Пакеты

`internal/`: `cli` (диспетчер, разбор флагов на `spf13/pflag`; напрямую импортирует `doctor`, `harness`, `install`, `lint`, `fsys`, `iostreams`, `lockfile`, `platform`, `prompt`); `doctor`, `lint`, `install` опираются на `harness`; `install` ещё на `render` и `hookcfg`; `render` импортирует `lockfile` и `platform`, `hookcfg` — только `platform`; `harness` — `frontmatter`, `fsys`, `lockfile`; листья `platform`, `lockfile`, `fsys`, `frontmatter`, `iostreams`; плюс `hooktest` (тесты хуков).

## Флаги

Общие для `add`/`remove`, если не указано иное:

| Флаг | Что делает | По умолчанию |
|------|-----------|--------------|
| `-p, --project PATH` | корень целевого проекта: `~` раскрывается, путь должен существовать, `$HOME` отклоняется | `.` |
| `-d, --domain D` | только `hooks`: домены (через запятую или повтором), из исходников которых берутся хуки | — |
| `-a, --agent P` | `claude\|codex\|cursor\|opencode\|all`, через запятую или повтором; также для `doctor`/`hooks` | автоопределение (ниже) |
| `--copy` | только `add`: копия-снэпшот вместо symlink | выключено (по умолчанию — symlink) |
| `-y` | принять значения по умолчанию: никаких вопросов и подтверждений (обязателен без терминала, если нет `--dry-run`) | выключено |
| `--dry-run` | ничего не пишет, только печатает план | выключено |

Платформа по умолчанию определяется по существующим `.codex/`, `.cursor/`, `.opencode/`, `.claude/` (если там не один только `skills-lock.json`) и платформам из lockfile; ничего нет — `claude`. Вывод печатает источник (`platforms: detected from ...`).

Link-режим для `.agents`, `.codex`, `.cursor`, `.opencode` внутри git-репозитория требует, чтобы каталог был в `.gitignore` (`git check-ignore`); иначе отказ — добавьте каталог или ставьте `--copy` (`--force` обходит). `add -y` заранее прогоняет установку вхолостую и при любом конфликте (в том числе чужие неотслеживаемые пути) падает с подсказкой (`-a claude`, `--copy` или убрать пути), ничего не записав.

Если `requires_env` домена называет незаданную переменную (сегодня только `obsidian` → `$OBSIDIAN_VAULT`) — ошибка для явно названного домена/скилла, предупреждение и пропуск для `all`. Зеркальный `requires_bin` (проверка через `$PATH`) пока не объявляет ни один домен.
