# code-build

Реализует уже утверждённый план из `swarm-report/<slug>-plan.md`: раздаёт задачи исполняющим агентам по зоне ответственности, гоняет тесты, пишет отчёт о реализации.

## Когда срабатывает

`/code-build <slug>` — после `/code-plan`, никогда до него.

## Что делает

Orchestrator, сам код не правит. Находит план, проверяет, что в нём не осталось нерешённых HIGH-блокеров, и раскладывает `affected_files` по исполняющим агентам (frontend / backend / devops / mobile) согласно таблице в `AGENTS.md` целевого проекта. Спавнит подходящих exec-агентов — параллельно, если фича задевает несколько слоёв, — и передаёт зависимому агенту заметки о контракте, если один слой меняет то, что нужно другому.

После того как агенты отчитались, проверяет `tests_result` каждого: блокирующий статус или упавший тест — не повод писать «готово», а повод показать провал как есть и остановиться. Итог — `swarm-report/<slug>-build.md`.

## Границы

Не заявляет успех без реального прогона тестов — Stop-хук `test-gate` следит за этим отдельно. Файл без сопоставленного агента — не угадывает исполнителя, спрашивает пользователя.

Если тест падает — [`code-debug`](../code-debug/README.md). После сборки — [`code-review`](../code-review/README.md).
