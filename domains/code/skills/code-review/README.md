# code-review

Проверяет готовое изменение против его плана: спавнит одного reviewer-субагента, который read-only и отчитывается вердиктом ship/rework с находками по severity.

## Когда срабатывает

`/code-review <slug>` — после `/code-build`.

## Что делает

Собирает план, отчёт сборки и diff (staged + unstaged либо относительно точки ветвления) и передаёт всё это одному reviewer-субагенту прямо в промпт — тот не перечитывает репозиторий заново. Reviewer код не правит, только находит и помечает severity. Orchestrator возвращает вердикт и находки без изменений.

## Границы

Ничего сам не чинит: при вердикте `rework` находки становятся входом для повторного `/code-build <slug>`, а не поводом редактировать код здесь же. Решение, что и как чинить, — за пользователем.
