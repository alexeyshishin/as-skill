# code-init

Создаёт `CLAUDE.md` в корне проекта — справочник команд и правил для Claude Code.

## Когда срабатывает

«Создай CLAUDE.md», «инициализируй правила проекта», «настрой CLAUDE.md», `/code-init`.

## Что делает

Определяет по проекту реальные команды (build/run/test/lint), карту каталогов и стиль
коммитов, затем пишет компактный `CLAUDE.md` (~90–120 строк) по лучшим практикам: сначала
команды и проверки, потом архитектура, git и подводные камни — не свалка запретов, а
справочник процессов.

В начало всегда зашиты четыре обязательных правила:

1. Не выполнять `git commit` — коммитит пользователь.
2. Всегда вызывать навык `/caveman`.
3. Не писать комментарии в коде.
4. Отвечать на русском.

Если в проекте стоит `code`-харнесс, в файл также попадают разделы:

- **Рабочий цикл** — кто кого зовёт: `/code-plan` → `/code-build` → `/code-review`, петля через `/code-debug`.
- **Исполнители для /code-build** — таблица «агент → зона → реальные пути проекта»
  (`backend` / `frontend` / `devops`), правила параллельного запуска и передачи контракта
  между слоями. Строки берутся из того, что реально найдено в репозитории и установлено в
  `.claude/agents/`; слой без агента (например, мобильный) помечается «нет исполнителя».
- **Memory Bank** — когда агенты пополняют `.memory-bank/`: только после того, как задача
  *полностью* выполнена (план закрыт, проверки зелёные, `/code-review` дал `ship`, блокеров
  нет). Пишет один агент за раз через навык `memory-bank`; нечего записывать — явный
  `NO_MEMORY_UPDATE`.
- **Модели** — рекомендация модели на каждую роль: Opus на план/ревью/дебаг, Sonnet на
  исполнителей.

## Регистрация хуков

Установщик кладёт хуки в `.claude/hooks/`, но Claude Code запускает хук только если он
перечислен в `settings.json`. Регистрацию делает скрипт `scripts/register-hooks.sh` — не
модель, поэтому токены на правку JSON не тратятся:

- `--dry-run` показывает по строке на каждый установленный хук: `present` или `would-add`;
- если есть `would-add`, `/code-init` один раз спрашивает согласие и запускает скрипт без
  флага;
- скрипт пишет только в `.claude/settings.json` проекта (на `$HOME` отказывается — глобальный
  `~/.claude/settings.json` не трогает), добавляет недостающие записи в `hooks.<Event>`,
  остальные ключи и чужие хуки оставляет, дубль не создаёт (запись в `settings.local.json`
  тоже считается), невалидный JSON не правит.

Какие хуки и с каким matcher регистрировать, каждый хук объявляет сам строкой в шапке:
`# register: <Event> [<matcher>]` (сейчас `test-gate` — Stop, `prettier-format` —
PostToolUse, `memory-bank-load` — SessionStart). Новый хук в `domains/code/hooks/` достаточно
снабдить этой строкой. Скрипт можно запускать и отдельно: `bash
.claude/skills/code-init/scripts/register-hooks.sh [--project DIR] [--dry-run]`.

Отказ, нет хуков или нет `jq` (хуки без него молча ничего не делают) — фраза про `test-gate`
в разделе «Рабочий цикл» не пишется, итог попадает в отчёт.

## Границы

Пишет `CLAUDE.md` и, с согласия, записи хуков в `.claude/settings.json` проекта — не делает
`git add`/`git commit`. Существующий `CLAUDE.md` не
перезаписывает без подтверждения (предлагает перезапись / слияние / отмену). Если рядом
есть `AGENTS.md` — ссылается на него через `@AGENTS.md`, а не дублирует. Команды не
выдумывает: чего нет в репозитории — того нет и в файле.
