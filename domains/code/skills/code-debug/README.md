# code-debug

Ищет корневую причину бага или упавшего теста: спавнит одного debugger-субагента, который воспроизводит проблему, перебирает гипотезы по цепочке и правит только то, на что указывают улики.

## Когда срабатывает

`/debug "<текст ошибки / упавший тест / что сломалось>"` (опционально `/debug <slug>`, если баг привязан к конкретной фиче) — когда тест падает, `/build` вернул `blocked`, или пользователь говорит «X перестало работать». Фичи не проектирует — это `/plan`.

## Что делает

Собирает симптом: текст ошибки, стектрейс или имя упавшего теста, плюс отчёт сборки, если дан slug. Спавнит одного debugger'а, который сначала диагностирует и только потом трогает код. Возвращает вердикт как есть — корневую причину, улики, фикс и результат повторного прогона — без пересказа.

Дальше маршрутизирует по исходу: `fixed` → предлагает `/review`; `root_cause_found` без фикса или `stuck` → показывает цепочку гипотез и отдаёт решение пользователю; `cannot_reproduce` → просит точные шаги воспроизведения вместо угадывания.

## Границы

Не патчит вслепую при `cannot_reproduce`. Сидит между `/build` и `/review` в цикле — Stop-хук `test-gate` не даст объявить «готово», пока тесты реально не прогнаны.
