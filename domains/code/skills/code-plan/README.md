# code-plan

Проектирует фичу до того, как написана первая строка кода: спавнит planner и skeptic, сталкивает их и пишет согласованный план в `swarm-report/`.

## Когда срабатывает

`/plan "<фича одним предложением>"` — перед `/build`, для любой фичи, которая трогает 2+ файла или имеет нечёткий scope. Для опечаток и однострочных правок не нужен.

## Что делает

Сам план не придумывает: читает Memory Bank, если она есть, и параллельно спавнит два субагента — planner пишет план, skeptic его атакует и ищет, что сломается. Дальше сводит их выводы сам: берёт план planner'а, применяет HIGH/MED правки skeptic'а, а то, что осталось нерешённым, выносит в `Blockers` — их снимает пользователь, не модель.

Результат — `swarm-report/<slug>-plan.md` с acceptance criteria, планом и списком блокеров.

## Границы

Код не пишет и не трогает. Пока в плане остаются нерешённые Blockers, идти дальше в `/build` не стоит — orchestrator сам об этом напоминает, но не блокирует принудительно.

Дальше по цепочке — [`code-build`](../code-build/README.md).
