# docs-c4

Рисует C4-диаграммы архитектуры (context, container, component) по реальному коду проекта: JSON-модель → SVG.

## Когда срабатывает

«Нарисуй C4», «схема архитектуры», «диаграмма контейнеров», «обнови схему», «draw a C4 diagram».

## Что делает

Находит в коде, что есть в системе и кто кого вызывает: сервисы — в `docker-compose`, манифестах Kubernetes и Helm, `Dockerfile`; хранилища — по образам и драйверам в манифестах; внешние системы — по SDK, base URL и переменным окружения; связи — по клиентам HTTP, gRPC, очередей, SQL и S3, вебхукам. Для каждого блока и стрелки держит ссылку на файл. Чего в коде нет, спрашивает одним сообщением.

Пишет модель `docs/architecture/c4-<level>.json`: слои сверху вниз — вызывающий сверху, вызываемый снизу, поэтому стрелки идут вниз; вверх — только обратные вызовы вроде вебхуков. На стрелке номер, что делает вызов и `[формат/транспорт]`; полное описание и протокол — в таблице связей под схемой. Однотипные узлы одного слоя собираются в boundary, одна стрелка от него заменяет одинаковые стрелки от каждого.

Рендерит SVG рядом с моделью: раскладывает узлы по сетке, ведёт стрелки ортогонально по полосам между слоями и коридорам, отжигом подбирает маршруты с минимумом пересечений, расставляет подписи так, чтобы они не наезжали на блоки, стрелки и друг на друга. Добавляет легенду и таблицу связей. Если документ с диаграммой есть на русском, делает пару `_RUS.json` / `_RUS.svg` с той же структурой.

Правила нотации — в разделе C4 diagrams правила [`docs-conventions`](../../rules/docs-conventions.md).

## Границы

Не рисует sequence-диаграммы и блок-схемы. Не правит SVG руками — только модель. Ревью готовой диаграммы — агент `docs-c4-reviewer`, правки по ревью — `docs-c4-writer`. Не коммитит.

## Чем укомплектован

[`references/model-format.md`](references/model-format.md) — поля модели, виды узлов, порядок слоёв, ручки раскладки, коды проверок.

[`references/example-container.json`](references/example-container.json) — полная container-модель книжного магазина: люди, фронтенды, API, воркеры в boundary, хранилища, внешние системы, вебхук.

[`scripts/check-c4.py`](scripts/check-c4.py) — проверка модели: схема, ссылки между слоями, узлами и рёбрами, рёбра внутри слоя, дубли, обратные стрелки (больше 20% — ошибка порядка слоёв), технология на узлах и стрелках, длина подписей, плотность. Плюс устаревший SVG (по хешу модели внутри SVG) и пара EN/RU: одинаковые id, порядок, рёбра, непереведённые подписи.

[`scripts/render.py`](scripts/render.py) — раскладка и SVG; `--png` через headless Chrome; `--seed` для другого варианта раскладки, удачный сохраняется в `layout.seed`, чтобы повторный рендер давал тот же файл.

```bash
python3 scripts/check-c4.py docs/architecture/c4-container.json
python3 scripts/render.py docs/architecture/c4-container.json --png /tmp/c4.png
python3 scripts/render.py docs/architecture/c4-container.json --seed 7
```

Коды выхода `check-c4.py`: 0 — чисто, 2 — есть ошибки (с `--strict` ещё и предупреждения), 1 — ошибка вызова. `render.py`: 0 — готово, 1 — ошибки в модели, 2 — SVG записан, но часть подписей не поместилась. Оба скрипта — Python 3.8+ без зависимостей.
