# memory-bank

Ведёт лёгкую «энциклопедию проекта» в `.memory-bank/`: архитектура, стек, конвенции, ключевые сущности, активные задачи. После значимого изменения предлагает точечное обновление или явно пишет, что обновлять нечего.

## Когда срабатывает

После реплик, которые могли изменить устойчивое знание о проекте: архитектурные решения, контракты API, конвенции, смена стека, новые задачи. Не срабатывает на локальные детали реализации, эксперименты, мелкие рефакторинги и правки стиля.

## Что делает

Три фазы:

1. **Оценка** — стабильный ли это факт и насколько важный (0–3). Предлагает обновление только при важности ≥ 2.
2. **Предложение** — блок `MEMORY_SUGGESTION` с путём, операцией (`create` / `update` / `append`), секцией и самим текстом. Перед этим читает существующий `.memory-bank/`, чтобы не плодить дубли и противоречия.
3. **Отказ** — блок `NO_MEMORY_UPDATE` с причиной в одно предложение. Молчание не допускается.

Структура: `index.md` (точка входа), `product-overview/`, `steerings/` (конвенции разработки и тестирования), `tech-details/`, `tasks/`. Если `.memory-bank/` нет, а факты важные, предлагает создать хотя бы `index.md`. При первом создании, если индекс ast-index есть (`test -f "$(ast-index db-path)"`), архитектуру, структуру и конвенции берёт из `ast-index map` и `ast-index conventions`, а не обходит дерево вручную; без ast-index — как раньше.

## Границы

Секреты, токены и приватные данные не записываются никогда. При сомнении обновление не предлагается — недостающий факт добавить легко, шумный подрывает доверие. Загрузку `index.md` в сессию делает хук `memory-bank-load.sh`, автообновление после сессии — `memory-bank-logger.sh` (оба в `domains/core/hooks/`). Накопившиеся патчи сворачивает `memory-bank-defrag`.
