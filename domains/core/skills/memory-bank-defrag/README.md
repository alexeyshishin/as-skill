# memory-bank-defrag

Дефрагментация memory bank проекта (`.memory-bank/` + auto-memory хоста): сверяет его с кодом и сжимает до текущего состояния. Те же факты, меньше текста.

## Когда срабатывает

`/memory-bank-defrag [ref|date]` — или «defrag the memory bank», «актуализируй memory bank», «причеши базу знаний». Необязательный аргумент (SHA или `YYYY-MM-DD`) переопределяет точку отсчёта из `.memory-bank/.defrag.yaml`.

## Что делает

1. Берёт точку отсчёта из `.memory-bank/.defrag.yaml` (`date` + `ref`): есть git и `ref` жив — диф от него; `ref` пропал после rebase/squash — коммит по `date`; git нет — файлы новее состояния; состояния нет — проверка всех утверждений по текущему дереву. От формата коммитов не зависит.
2. **Актуализация** — по изменениям с точки отсчёта: устаревшие факты, битые ссылки, решённые вопросы и задачи, незафиксированные решения — каждое с доказательством (SHA, `file:line`).
3. **Компакция** — всегда, по всему memory bank: цепочка поправок → одно текущее утверждение; рассказ «как шли к решению» → факты; выполненная задача → итог в профильный файл, в `tasks/` одна строка со ссылкой; закрытый вопрос → ответ в профильный файл; дубли → одно место + ссылки; `index.md` ссылается на все файлы и не больше 16 KB.
4. Проверяет `grep`-ом остатки ретайрнутого, показывает diff и сводку. `.defrag.yaml` обновляется, только если что-то изменилось.

Факты проверяются по живому репозиторию: если память противоречит коду, верен код. Уже сжатый текст не перефразируется — повторный запуск без изменений ничего не правит.

## Границы

Меняет только документацию и знания, продуктовый код не трогает. Сырые источники (транскрипты, дампы чатов) остаются дословными. Ничего не выдумывает и не пишет в историю «актуализировано такого-то числа». Без явной просьбы не коммитит; коммит — одна строка по конвенции проекта. В unattended-режиме открывает PR из ветки `docs/memory-bank-defrag-<YYYY-MM-DD>`, в `main` не пушит; без правок — ни ветки, ни PR.
